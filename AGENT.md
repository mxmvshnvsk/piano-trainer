# Правила проекта Piano practice

## Назначение и границы

Это офлайн-тренажёр фортепиано для начинающих: короткое задание, исполнение, проверка и понятная обратная связь. React + TypeScript + Vite, публикация в GitHub Pages. Звук обрабатывается на устройстве, без отправки на сервер. Не добавляйте регистрацию, сервер или обязательную сеть для тренировки.

Инструкции пользователя имеют приоритет над соглашениями этого файла. Сохраняйте существующие настройки и упражнения при изменении формата данных. Эксперименты в `output/` не являются источником истины для рабочего интерфейса.

## Терминология

Пользуйтесь принятыми музыкальными терминами. Новый термин сопровождайте коротким, конкретным пояснением, когда оно помогает начинающему. Не заменяйте термин выдуманным названием и не добавляйте объяснения, которые не соответствуют реально сыгранным звукам.

| Понятие | Русский интерфейс | English |
| --- | --- | --- |
| Основной тон в басу | Основной вид · основной тон внизу | Root position · root in the bass |
| Следующий звук аккорда в басу | Первое обращение | First inversion |
| Регистр и интервалы между голосами | Расположение | Voicing / spacing |
| Текущий пресет переноса только баса вниз | Бас в большой октаве | Bass in the great octave |
| Номера используемых пальцев | Аппликатура | Fingering |
| Центральный звук лада | Тоника | Tonic |
| Мажорный лад | Ионийский | Ionian |
| Натуральный минорный лад | Эолийский | Aeolian |
| Длительность половины целой ноты | Половинная нота / пауза | Half note / rest |
| Длительность четверти целой ноты | Четвертная нота / пауза | Quarter note / rest |
| Длительность восьмой части целой ноты | Восьмая нота / пауза | Eighth note / rest |
| Время до начала следующего звука | Время между началами нот | Inter-onset interval |

- Не писать «основное положение» вместо «основной вид». «Мелодическое положение» — отдельное понятие о верхнем голосе.
- Обращение, расположение и аппликатура — разные свойства. Объединённый список текущих пресетов называется «Вариант аккорда», а не «Обращение».
- Перенос только баса в низкий регистр не доказывает широкого расположения остальных голосов. Текущий `wide` подписывается по реальному поведению: «Бас в большой октаве».
- Первое обращение трезвучия — секстаккорд, но не любое первое обращение любого аккорда. `C6` — мажорный аккорд с добавленной секстой; это не обозначение первого обращения в принятой здесь буквенной системе.
- Не называть все трёхзвучные аккорды трезвучиями: `sus2` и `sus4` заменяют терцию секундой или квартой. Не утверждать, что тренажёр проверяет разрешение задержания.
- Для септаккордов различать малый мажорный (`7`), большой мажорный (`maj7`), малый минорный (`m7`), большой минорный (`m(maj7)`) и уменьшённый (`dim7`). Функцию доминанты без тонального контекста не назначать автоматически.
- Для лада, гаммы и аккорда не использовать взаимозаменяемые названия. Дорийский лад — не отдельный тип аккорда. Явно выбранный лад определяет ноты гаммы независимо от настроения.
- Для симметричных коллекций (целотонная, хроматическая) различать выбранный начальный звук и функциональную тонику.
- Исходная октава задаётся до применения обращения или переноса баса. На экране показывать фактические ноты и их октавы. При игре двумя руками объяснять, к какой руке относится настройка.

## Буквенная нотация и написание звуков

- Принята международная система: `C D E F G A B`, где `B` — си; `C4` — до первой октавы. Не смешивать её с немецкой системой `H/B`.
- В буквенном обозначении `E♭m` знак альтерации находится после буквы. На нотном стане знак стоит перед нотой. Эти способы записи нельзя смешивать.
- Крупные обозначения собирать компонентом `ChordSymbol`: основной тон, компактный знак альтерации и уменьшенный суффикс аккорда. `m` отличается от `maj7`. Числа и расширения допускают приподнятое начертание. Не растягивать бемоль и диез до размера основной буквы.
- Для музыкальных глифов использовать локальный Bravura / SMuFL, а не случайный символ из системного шрифта. Сохранять лицензию OFL и офлайн-загрузку шрифта. У декоративных глифов должна быть доступная текстовая подпись; не озвучивать коды Private Use Area.
- MIDI определяет высоту, но не буквенное написание. Подписи ожидаемых звуков строятся по ступеням выбранной гаммы или составу аккорда: `G♯` в ми мажоре, `G♭` в ми-бемоль миноре, `B♯` в до-диез мажоре. Не заменять их автоматически энгармоническими названиями из общей таблицы клавиш.
- Обращения и переносы меняют октаву, но сохраняют буквенное имя звука. Если нужны дубль-диез или дубль-бемоль, показывать их корректно. Номер октавы относится к написанному звуку: `B♯4` энгармоничен `C5`.
- Номера на клавишах обозначают порядок звуков, не пальцы. Микрофон не определяет руку, палец, нажатие педали или физическое отпускание клавиши.

## Ритмическая нотация и оценка

- Четвертная нота: закрашенная головка со штилем. Половинная: незакрашенная головка со штилем. Восьмая: закрашенная головка, штиль и флажок. Точка увеличивает длительность на половину исходной.
- Для каждой длительности использовать соответствующий знак паузы. Половинная пауза лежит на линейке; не подменять все паузы одной самодельной фигурой.
- Знаки рисует `RhythmGlyph` из таблицы SMuFL. Ритмический рисунок без высот не выдавать за полноценную нотную запись на пятилинейном стане.
- Темповый знак показывает единицу пульса: в простых размерах — четверть, в `6/8` — четверть с точкой, две основные доли на такт. Если подписаны числа под длительностями, их единицы должны согласовываться со счётом такта.
- «Музыкальный интервал» обычно означает соотношение высот. В статистике ритма уточнять, что измеряется время между началами нот.
- Точность длительностей здесь вычисляется по последовательным началам звуков, а не по удержанию или отпусканию клавиш. Не заявлять проверку легато, штриха, туше или длительности физического нажатия.
- Моменты атак и метронома сравнивать по аудиочасам, а не по времени получения результатов модели. Не скрывать задержки устройства фиктивным результатом «мгновенно».

## Язык интерфейса

- Поддерживать русскую и английскую версии одновременно. Названия аккордов, ладов, октав и общую терминологию хранить централизованно. Не оставлять русские слова в английском интерфейсе через случайный fallback.
- Писать коротко и по существу: действие, состояние или конкретная ошибка. Не возвращать удалённые пользователем фразы «Готов, когда ты готов», «Начни попытку» и служебный текст «Локальная разработка».
- Сохранять выбранные пользователем короткие названия «Трудное», «В сложное», «Поток».
- Различать получение звука, обработку и уверенный результат. При низкой уверенности просить повторить; не выдавать предположение за достоверную ошибку.
- Подсказка «третью ноту выше» относится к порядку нот, не к третьему пальцу. Числа на клавишах не являются аппликатурой.
- Сообщение об окончании попытки нейтрально: «Упражнение завершено», даже если ничего не сыграно. «Всё верно» показывается только после успешной проверки.
- В технических статусах говорить о доступном действии пользователя, не о внутренних деталях реализации. Например, «Офлайн-режим недоступен», а не «кэш упал».

## Микрофон и распознавание

- Чувствительность и измеренный фон сохраняются для текущего браузера/устройства. При открытии сохранённого упражнения использовать текущую настройку микрофона, а не старую настройку из упражнения.
- Ползунок меняет усиление и порог сигнала, а не требования к точности высоты. Измерять фон без игры; во время измерения распознавание приостановлено, индикатор работает. После изменения усиления/фона не оценивать результаты старого аудиоокна.
- Шкала и запуск распознавания используют один порог громкости. Не вводить дополнительный порог пиков, который непредсказуемо отсекает тихую одиночную ноту. Перегрузку входа отличать от чрезмерного программного усиления.
- Слабая атака допустима при достаточно долгом уверенном определении высоты. Слабые гармоники и короткие выбросы не считать нотами. Начало перекрывающегося окна на уже звучащей ноте не считать новой атакой; не засчитывать последовательный аккорд как одновременный.
- Различать работающий микрофон, получение звука, обработку и отсутствие распознанных нот. Длительное ожидание устройства/обработки должно завершаться понятной ошибкой. Поздно полученный после отмены поток обязательно останавливать.
- Для быстрого пути выполнять одно фиксированное окно модели напрямую через WASM; не возвращать двухсекундное ожидание записи или обёртку с неподдерживаемым `fill`. Численно сверять результаты с эталонной обработкой; проверять последовательность коротких окон, а не только каждое окно отдельно. Измерения на компьютере не выдавать за замеры на iPad.
- До итоговой оценки дождаться уже начатой обработки и короткого хвоста записи. Хвост нужен для контекста и устойчивости нот, начатых до дедлайна; новые ноты после дедлайна не засчитывать. Отмена попытки не должна переносить её результат в следующую.
- Зелёные клавиши обозначают распознанные высоты. Если высоты совпали, но атака/устойчивость не подтверждены, показывать нейтральное «Ноты верные · повтори», а не «Не удалось распознать ноты» и не успешный зачёт.

## Вёрстка и проверки

- Сохранять спокойный интерфейс, компактный хедер, ограниченную высоту клавиатуры и общую компактную группу задания с клавишами. Лишняя высота окна остаётся вокруг группы.
- Футер имеет постоянную область по высоте; появление кнопки установки или изменение статуса не добавляет строк. Ссылка автора остаётся по геометрическому центру.
- Общие селекторы имеют поиск и навигацию стрелками, Enter, Esc, Tab, Home/End; недоступные варианты пропускаются. Не возвращать системные синие выпадающие меню.
- При изменении нотации проверять как минимум бемоль, диез, минор, септаккорд и составные суффиксы; в ритме — половинную, четвертную, восьмую, точку и разные паузы. Проверять светлую и тёмную темы, уменьшение анимации, окно `1280×650`, телефон `390×844` и вертикальный планшет `834×1194`.
- Проверять музыкальные данные по MIDI и отдельно их написание, чтобы визуальное исправление не меняло оценку высоты. Исправление неверно построенных упражнений проверять музыкальными тестами.
- После изменения поведения запускать `npm test`; перед завершением изменения — `npm run build`. Для чисто визуальной правки достаточно сборки и проверки в браузере. Не добавлять тесты, которые лишь повторяют верстку.
